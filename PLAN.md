# PLAN.md — js13k 2026 Foundation

**Repo**: js13k-2026-orb-ruins  
**Stack**: Odin → `js_wasm32` → minimal JS glue + Canvas 2D. No external libs. Core only.  
**Constraint**: Final ZIP ≤ 13 312 bytes. Everything lives inside that.

Theme interpretation (Unicorns & Rainbows): a single glowing orb (the last unicorn light / rainbow core) pulses in the blackened ruins of a fallen world. Atmosphere first.

## Grug Brain + Ponytail Complexity Ladder (mandatory)

We stop at the first rung that holds:

1. **Does this need to exist?** Speculative = skip. One-line note why.
2. **Already in this codebase?** Reuse helper / pattern.
3. **Stdlib / core does it?** Use it.
4. **Native platform feature?** Canvas 2D over WebGL. Touch events over gesture libs. CSS for nothing fancy.
5. **Already-installed dep?** None exist. Never add one.
6. **Can it be one line / one proc?** Do that.
7. Only then: minimum working code.

No “nice architecture”. No ECS. No scene graph. Flat data + procs. Procedural everything.

## Goals for this foundation (end-to-end vertical slice)

- Mobile Web first (touch).
- Dark screen, one pulsing glowing orb that casts soft pixel shadows on desolate ruin geometry.
- Atmospheric pixel-art 2D platformer feel.
- Virtual joystick: appears wherever the thumb first touches (right side preferred, but free).
- Two static buttons fixed in the **left** corner (Jump + secondary action, e.g. dash or interact).
- Character movement that prioritises **feel**. Model after Celeste (coyote time, jump buffer, variable jump height, corner correction, responsive accel/decel).
- All assets generated by code (no PNGs, no base64 images).
- Helper procs that can stamp different ruin tiles / props at world locations.
- Simple camera with easy trigger points for predetermined cinematic moves (look-at, pan, zoom hold).
- Verification scripts/tests that fail the build or print hard errors if size rules are broken or required files missing.

## Technical Approach

### Build pipeline (minimal)
- `odin build . -target:js_wasm32 -out:game.wasm -o:size` (or speed then strip).
- Tiny `index.html` + `odin.js` (copied from Odin core) + the wasm.
- One small `game.js` that creates the canvas, wires touch, calls exported Odin procs each frame (`update`, `draw`, input setters).
- Zip script that produces the submission zip and asserts size ≤ 13312.

### Size discipline from day 1
- Every commit runs a size check.
- Prefer `u8`/`i16`/`f32` where possible.
- No strings in hot paths.
- Procedural drawing > tables of pixels when the table would be larger.

### Movement (Celeste-inspired starting point)
Core loop (all in one file for now):

```
// simplified
vel.x = approach(vel.x, target_speed * input.x, accel * dt)
if on_ground {
    coyote = COYOTE_TIME
} else {
    coyote -= dt
}
if jump_pressed && (on_ground || coyote > 0) {
    vel.y = JUMP_SPEED
    coyote = 0
    jump_buffer = 0
}
if jump_held && vel.y < 0 {
    vel.y += GRAVITY * 0.5 * dt   // half gravity at apex
} else {
    vel.y += GRAVITY * dt
}
// jump buffer, corner correction, etc.
```

Numbers tuned later by feel. Start with values close to Celeste’s published numbers scaled to our pixel size.

### Rendering
- Single canvas, pixel-perfect (integer coords, no AA).
- World is a simple tilemap or sparse list of rects/props generated at start.
- Orb = circle + soft glow layers (multiple fillRect or arc with alpha).
- Shadows: for each lit surface, simple projected dark rect or dithered pixels based on orb position. Keep it cheap.
- Camera: offset + optional lerp or scripted path.

### Input (mobile first)
- Touchstart → if left 1/4 of screen and in button zones → button.
- Else → create virtual stick at touch point (or fixed right zone).
- Stick returns normalised vector.
- Keyboard fallback for desktop testing (WASD / arrows + Z/X).

### Camera triggers
Simple array of triggers:

```odin
CameraTrigger :: struct {
    rect: Rect,
    mode: enum { LookAt, PanTo, Hold },
    target: Vec2,
    duration: f32,
}
```

When player AABB overlaps, fire once (or re-fire if flagged). Camera state machine is 20 lines.

### Asset generation helpers
```odin
gen_ruin_wall :: proc(x, y, w, h: i32, variant: u8)
gen_pillar :: proc(x, y: i32)
gen_rubble :: proc(x, y: i32, seed: u32)
gen_glow_orb :: proc(cx, cy, radius, pulse: f32)  // called every frame
```

All draw directly into the canvas context via foreign or via a small pixel buffer we blit.

### Verification tests
- `make size` → builds, zips, fails if > 13312.
- `make check` → ensures index.html exists at root of zip, no external URLs in sources, wasm exports the required symbols.
- Simple unit-ish tests in Odin that run under `odin test` for movement math (coyote, buffer) so we don’t regress feel while iterating.

## Order of work (foundation)

1. Skeleton: Odin js_wasm32 that clears canvas to black and draws a pulsing circle. Export update/draw.
2. Touch + virtual stick + two left buttons. Keyboard fallback.
3. Player rect that moves with the stick, simple gravity + jump (already with coyote + buffer).
4. Procedural ruins: a few walls, floors, one pillar. Collision AABB.
5. Orb that casts crude shadows (darken tiles based on distance/angle).
6. Camera follow + one hard-coded trigger zone that pans.
7. Size pipeline + verification scripts.
8. Tune movement numbers until it feels good on phone.

Stop. Ship the vertical slice. Only then expand content.

## Non-goals for foundation
- Audio (add later if bytes remain).
- Particles beyond the glow.
- Multiple levels.
- WebGL.
- Any library.
- Fancy shaders.
- Save system.

## Risk notes
- WASM + odin.js overhead is real. Measure early. If too fat, fall back to pure JS (but try Odin first as requested).
- Canvas 2D fill/stroke is fine for pixel look if we stay integer and low draw-call.
- Touch joystick must not fight the two left buttons.

This is the entire plan. Execute the ladder. Keep it small enough to feel.
